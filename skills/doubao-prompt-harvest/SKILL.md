# 扒豆包「发现」页做同款提示词

豆包网页版没有「AI 创作 · 发现」的社区作品流，Mac 客户端的发现页也不一样（多半是海报模板），只有手机 App 有。所以要用 Mac 上的「iPhone镜像」操作手机。核心做法是在做同款面板里全选复制提示词，通过通用剪贴板传到 Mac，再粘贴进「文本编辑」暂存，最后一次性读出来整理。这样拿到的是原文，不会有识别错字，很长的视频提示词也不会漏。

## 绝对不能做的

- **绝不点做同款面板右下角的蓝色发送箭头**，点了会真的生成并消耗用户额度。所有点击都要离它远一点：展开图标就在发送键正上方，面板位置还会变，所以不要去点展开图标。
- 不点赞、不评论、不关注，不改豆包里的任何设置。

## 准备

1. 用户的 Mac 要开着 Claude 桌面 App，并且开启电脑操控。手机和电脑在采集期间都不要动，Mac 不要睡眠。
2. 用 computer_resolve_access 解析「iPhone镜像」和「文本编辑」（要用中文名解析），申请权限时加上 clipboardRead。再用 computer_request_full_control 申请全屏控制。后台模式在窗口不在当前桌面时点不动，而且 cmd+a/cmd+c 只能用全屏的 key 按键发送，菜单里的拷贝会被拦。中途连接断开后，权限要重新申请。
3. 用户如果停在全屏 App 里，iPhone镜像窗口会在别的桌面。用 computer_open_application 打开 iPhone镜像后，第一次点击只起激活窗口的作用。
4. 用镜像的菜单「显示 › 主屏幕」和「显示 › 聚焦」，输入「豆包」打开 App，点左上角抽屉里的「AI 创作」，停在「发现」标签。
5. 打开「文本编辑」，点「新建文稿」，按 cmd+shift+t 切成纯文本。用 computer_app_menu 点「窗口 › 移动与调整大小 › 右下」，把窗口挪到不挡手机镜像的地方（拖动到桌面空白处会被拦）。然后在文档里先打一个标记，例如 =====START=====。
6. 整屏截一张图，量出 iPhone镜像窗口的位置，推算下面这些坐标。窗口可能会自己挪位，每轮都用结尾的缩放截图确认一下。
   - 返回键：手机画面左上角箭头
   - 做同款按钮：详情页右下方白色按钮的中心
   - 激活点：手机状态栏中间（在详情页点这里没有副作用）
   - 文本编辑正文区域里的任意一点

## 单条动作序列

在 computer_batch 里连续执行：

1. 点作品卡片，等 3 秒。
2. 点「做同款」，等 2.3 秒，再在同一位置点一次，等 1.2 秒。第一次常因为加载没开面板；如果已经开了，第二次会落在输入框里，只是移动光标，没有副作用。
3. 按 cmd+a、cmd+c，等 1.3 秒让通用剪贴板同步。
4. 对手机区域缩放截一张小图（scale 0.25），用来记下作者、图片/视频、模型和比例。
5. 点文本编辑，按 cmd+down，输入 \n=====\n，再按 cmd+v。
6. 点激活点，等 0.5 秒；点返回（关掉面板），等 1 秒；再点一次返回（回到发现页），等 1.5 秒。

一个 batch 里放 4 条，每条之间加一张发现页的小缩略图作为检查点。最后一条做完后滚动发现页，并截一张清楚的图用来定位下一组卡片。remote bridge 规定一个 batch 的等待时间合计不能超过约 50 秒，5 条会超。

## 滚动和选卡片

- 镜像里的拖拽滑不动，只能用滚轮。100 格大约只滚 90 像素，一次大约发 5–6 个 100，刚好翻过一屏旧卡片。滚完要等 2.5 秒再截图，不然还有惯性，点击会落到别的卡上。
- **只点完整露出来的卡片**。点半截在屏幕顶部的卡，返回后发现页会跳一下，后面的坐标就全错了，会一连抓到重复的。
- 避开底部中间悬浮的「开始创作」按钮。
- 卡片右上角有播放图标的是视频；视频的做同款面板会带参考图，模型是 2.0 Fast/Mini，比例写「自动·10s」。
- 每条的使用人数从发现页卡片底部读。

## 出错了怎么处理

- **做同款两次都没打开**：剪贴板还是上一条，文本编辑里会多一条重复，在元数据里记成 DUP。这时连点两次返回，第二次会点到发现页左上角的≡，打开抽屉。点抽屉里的「AI 创作」就能回去，滚动位置会保留。
- **点到了别的作品**：照缩略图里的作者名正常记录元数据，重复的按原文去重。
- **「Claude 的窗口抢了键盘焦点」**：先截图，看停在哪一步，再从那一步继续。
- **连不上电脑**：只重试一次，不行就让用户看 Mac 有没有睡眠、Claude App 有没有开着，恢复后重新申请权限。

## 记录和整理

- 每处理完一个 batch，就在工作目录的元数据文件里按粘贴顺序追加一行：作者 | 图片或视频（带几张参考图）| 模型 | 比例 | 使用人数。重复的一条写 DUP。这样和文本编辑里的段落一一对应。
- 放慢节奏也没关系，但不要每条都单独读一次剪贴板再写文件，那样慢一倍。
- 收尾时在文本编辑里按 cmd+a、cmd+c，用 computer_read_clipboard 一次读出全部内容，写入工作目录。按 \n=====\n 切分，和元数据对齐并检查条数一致，去掉 DUP 和原文重复的。
- 想分批交付就在文本编辑里打一个新标记（例如 =====BATCH2=====），下次只取标记后面的部分。
- 整理成一个 HTML Artifact：可以按关键词搜索，按全部、图片、视频、01000 人以上用过筛选，每张卡片显示编号、作者、使用人数、类型、模型、比例和原文，长文折叠成「展开全文」，配「复制」按钮（复制失败就选中文字）。已经有这个页面的话，就更新同一个页面，不要新建。
- 原文里如果有不安全的做法（比如口含干冰吐雾），在那条下面加一句提醒。
- 结束时告诉用户文本编辑里的未命名文档可以不保存直接关，并调用 computer_release_lock 释放电脑。

## 节奏参考

稳定之后，大约每 4 条用 80–90 秒。发现页是无限刷新的推荐流，没有「全部」这个终点，要和用户说清楚；一般每 50–100 条交付一次，并问要不要继续。
